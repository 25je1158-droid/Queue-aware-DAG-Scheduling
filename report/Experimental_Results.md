## 2. Baseline algorithm comparison

The four policies use the same SUMO trace and generated workload for the default 20-vehicle experiment. They also use the same DAG ready-task ranking and CPU-sharing rule; the server-selection policy is the variable being compared. All candidates are screened using the same modeled coverage and contact-time feasibility condition.

| Server-selection policy | Applications completed | Mean application completion time | Mean queue wait | Completed-task deadline violations |
|---|---:|---:|---:|---:|
| Random | 19 / 20 | 6.4105 s | 0.8975 s | 0 |
| Nearest | 18 / 20 | 23.5056 s | 4.9508 s | 22 |
| Highest CPU | 20 / 20 | 3.7800 s | 0.2489 s | 0 |
| Proposed Queue-Aware | 20 / 20 | 3.6500 s | 0.2241 s | 0 |

In this run, Proposed Queue-Aware improves mean application completion time over Highest CPU by 0.13 seconds (approximately 3.44%). This is a modest improvement. It should not be described as statistically significant based on this one run alone.

The sensitivity experiment runs all four policies for 10, 20 and 40 selected vehicles, with task-generation seeds 21, 42 and 84. It reuses the same mobility trace and varies the number of selected vehicles and generated task workloads. The table below reports the mean across the three seeds.

|---:|---|---:|---:|---:|---:|
| 10 | Random | 6.8067 ± 0.2290 | 0.8374 ± 0.0555 | 0.00 | 100.00% |
| 10 | Nearest | 14.0100 ± 0.3676 | 2.4896 ± 0.0719 | 0.00 | 100.00% |

| 20 | Nearest | 23.3259 ± 0.2556 | 4.8466 ± 0.1127 | 22.33 | 90.00% |
| 20 | Highest CPU | 3.6383 ± 0.1257 | 0.2220 ± 0.0241 | 0.00 | 100.00% |

The proposed policy matches Highest CPU at the 10-vehicle load and gives modest mean completion-time and queue-wait improvements at 20 and 40 vehicles. This indicates that the queue-aware score can help under the tested workloads, but the advantage is not large in every scenario. The current sensitivity experiment does not generate separate SUMO traffic-density traces; it uses different subsets of one fixed trace.

## 4. Reproducibility

From the repository root, run:

```bash
python src/phase2_simulation.py
python src/algorithm_comparison.py
python src/run_sensitivity_experiments.py
```

The scripts regenerate the corresponding CSV and PNG outputs under `results/`.

## 5. Interpretation and limitations

The experiment supports the claim that the proposed heuristic is operational in the configured simulation and can reduce predicted application completion time relative to selected baselines in some tested conditions. It does not establish global optimality, broad statistical superiority or real-world performance. Further evaluation should use more random seeds, independently generated SUMO traffic densities, more DAG structures, calibrated wireless models and optimization-based baselines.
